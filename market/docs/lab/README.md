# آزمایشگاه مجازی PushRSP

## نصب

وابستگی‌ها: `avr8js`, `@monaco-editor/react` (+ monaco). روی سرور برای کامپایل: `gcc-avr`, `binutils-avr`, `avr-libc`.

```bash
cd /opt/pushrsp/app
npm install
npm run lab:sync   # اختیاری — همگام‌سازی Adafruit CAD
npm run test:lab
npm run build
systemctl restart pushrsp-market
```

مسیر عمومی: `/pushrsp/lab` (basePath).

## شبکه‌ی ۰٫۱ اینچ و اتصال (netlist)

- واحد بوم: **۱۰ = ۰٫۱ اینچ (۲٫۵۴mm)**، همان گام بردبورد و هدرها. مختصات همه‌ی پین‌ها مضرب ۱۰ است و `width + height` هر قطعه مضرب ۲۰، تا پین‌ها بعد از چرخش ۹۰° هم روی شبکه بمانند. تست `netlist.test.ts` این قاعده را برای همه‌ی قطعه‌ها در هر چهار زاویه چک می‌کند.
- بردبورد ۸۳۰ نقطه است (۶۳ ستون × a–j + چهار ریل ۵۰تایی). هر سوراخ یک پین با `signal: "passive"` است و نوارهای داخلی در `internalNets` تعریف شده‌اند.
- `src/lab/netlist.ts` مدار را به شبکه‌ها (net) تبدیل می‌کند. دو پین وقتی هم‌شبکه‌اند که سیم بینشان باشد، داخل خود قطعه به هم وصل باشند (`internalNets`، مثل سه GND برد Uno)، یا **روی یک نقطه‌ی بوم بنشینند**؛ یعنی «فرو کردن پایه در سوراخ» همان هم‌مکانی است و سیم نمی‌خواهد.
- اعتبارسنجی (`wiring/validate.ts`) و روشن شدن LED (`litLeds`) فقط با شبکه‌ها کار می‌کنند. LED وقتی روشن می‌شود که آندش (مستقیم یا از راه مقاومت) به خروجی HIGH یا تغذیه برسد و کاتدش به GND برد.

## افزودن قطعه

1. تعریف را در `src/lab/registry.ts` اضافه کنید (`ComponentDef` کامل). پین‌ها را روی شبکه‌ی ۱۰تایی بگذارید و پایه‌هایی را که داخل قطعه به هم وصل‌اند در `internalNets` بیاورید.
2. در صورت وجود محصول فروشگاه، `catalogSlug` و `CATALOG_SLUG_MAP` را در `product-adapter.ts` تنظیم کنید.
3. اگر رفتار شبیه‌سازی ندارید: `simulationStatus: "wireable"` یا `"3d-only"` — هرگز پین ساختگی نزنید.
4. قالب اختیاری در `src/lab/templates/`.
5. تصویر روی بوم: یک تابع در `src/lab/visuals/part-art.tsx` (در همان جعبه‌ی `width×height`، هم‌راستا با `pins[].x/y`). مدل سه‌بعدی بازرس: یا `modelUrl` به یک GLB واقعی (پایین را ببینید) یا یک تابع در `src/lab/visuals/models-3d.ts` برای مدل ساده‌شده‌ی درون‌کد؛ بدون این دو، قطعه با شکل پیش‌فرض نمایش داده می‌شود.

## میز کار (`/lab/workspace`)

- تمام‌صفحه؛ هدر و فوتر سایت در `components/site-chrome.tsx` برای این مسیر خاموش است.
- ساختار: `lab-workspace.tsx` (state، تاریخچه‌ی واگرد، موتور) ← `workspace-topbar`، `parts-panel`، `board-canvas`، `bottom-panel` (کد/سریال/گزارش/بررسی/BOM)، `inspector`، `onboarding-tour`.
- هندسه (چرخش، snap، fit، و LEDهایی که واقعاً از D13 تغذیه می‌شوند): `src/lab/geometry.ts` با تست.
- میان‌بُرها: `Ctrl+Enter` اجرا، `Ctrl+Z`/`Ctrl+Shift+Z` واگرد/ازنو، `Del` حذف، `R` چرخش، `Esc` لغو، `Ctrl+C`/`Ctrl+V`/`Ctrl+D` کپی/چسباندن/تکثیر، `Ctrl+A` انتخاب همه، کلیدهای جهت‌نما یک سوراخ (`Shift` = پنج سوراخ).
- سیم‌کشی (`board-canvas.tsx` + `wiring/route.ts`):
  - **ساختن سیم:** از پین بکشید و روی پین مقصد رها کنید، یا روی دو پین پشت سر هم بزنید. پین‌ها از ۱۶ پیکسلی آهنربایی جذب می‌کنند؛ سوراخ‌های بردبورد فقط وقتی دقیقاً رویشان باشید.
  - **خم:** وسط کشیدن سیم، کلیک روی فضای خالی یک خم قائم می‌سازد. `Shift` = خط آزاد، `Backspace` = حذف آخرین خم.
  - **ویرایش:** سیم انتخاب‌شده دستگیره‌ی خم (کشیدنی؛ دوبار کلیک = حذف)، دستگیره‌ی + وسط هر قطعه‌ی سیم (= خم جدید) و دستگیره‌ی دو سر دارد. سر سیم را می‌شود به پین دیگری برد و مسیرش قائم می‌ماند. رنگ سیم در پنل جزئیات انتخاب می‌شود.
- انتخاب چندتایی: `Shift`+کلیک، یا `Shift`+کشیدن روی فضای خالی یا روی بردبورد (کادر انتخاب). قطعه‌های انتخاب‌شده با هم جابه‌جا می‌شوند و خم‌های سیم‌های بینشان هم همراهشان می‌رود.
- کامپایل نیاز به ورود دارد (`/api/lab/compile`). اگر کامپایل ممکن نباشد و کد شبیه Blink باشد، فرم‌ویر آماده‌ی Blink اجرا و این موضوع صریحاً در گزارش نوشته می‌شود.

## کامپایلر و شبیه‌ساز

- `POST /api/lab/compile` کد Arduino را با `avr-gcc -mmcu=atmega328p` و هسته‌ی کوچک `scripts/lab-shim/` به Intel HEX تبدیل می‌کند. `main()` اول `__lab_init()` را صدا می‌زند تا تایمرها، PWM و ADC مثل هسته‌ی واقعی تنظیم شوند.
- **هسته‌ی shim** (`Arduino.h` و `Servo.h`):
  - زمان و PWM: `millis` و `micros` و `delay` روی Timer0، و `analogWrite` روی D3/D5/D6/D9/D10/D11 با PWM سخت‌افزاری.
  - ورودی و صدا: `analogRead` با ADC، `tone` و `noTone` روی Timer2، و `pulseIn` واقعی.
  - سریال: `Serial` با دریافت مبتنی بر وقفه (`available`/`read`/`parseInt`) و `print` کامل.
  - سروو: کتابخانه‌ی Servo روی Timer1 با پالس واقعی ۵۴۴ تا ۲۴۰۰µs.
  - Wire و LiquidCrystal هنوز پشتیبانی نمی‌شوند و صادقانه رد می‌شوند.
- **شبیه‌ساز:**
  - `engine/avr-runner.ts` میکروکنترلر avr8js را می‌سازد و برای هر پین (D0 تا D13 و A0 تا A5) سطح، duty سیگنال PWM، فرکانس (میانه‌ی سه دوره‌ی آخر) و پهنای آخرین پالس را اندازه می‌گیرد.
  - `engine/avr8-worker.ts` همان را با ساعت واقعی هم‌گام اجرا می‌کند (چرخه‌ها = زمان دیواری × ۱۶MHz × سرعت) و هر ۳۳ms یک frame می‌فرستد.
- **مدار:** `circuit.ts` بین مدار و برد پل می‌زند.
  - ورودی هر پین از روی شبکه تعیین می‌شود: GND، تغذیه، وایپر ولوم، مقاومت pull-up یا pull-down، یا شناور (که در آن صورت pull-up داخلی را می‌خواند).
  - خروجی‌ها از روی frame به روشنایی LED، زاویه‌ی سروو و فرکانس بازر تبدیل می‌شوند.
  - دکمه‌ی فشرده در netlist دو طرفش را به هم وصل می‌کند (`buildNetlist(…, { closed })`).
- **در حین اجرا:** روی دکمه کلیک کنید و نگه دارید، ولوم را بالا و پایین بکشید (`Alt`+کشیدن قطعه را جابه‌جا می‌کند)، و در Serial Monitor متن بفرستید. صدای بازر با WebAudio پخش می‌شود.
- **تست با فرم‌ویر واقعی:** `engine/__fixtures__/*.ino` با `npx tsx scripts/lab-build-fixtures.ts` به hex کامپایل و commit می‌شوند (CI به avr-gcc نیاز ندارد). `avr-runner.test.ts` زمان‌بندی، PWM، سروو، tone، ملودی، pull-up، سریال و ADC را روی همین hexها چک می‌کند. بعد از هر تغییر در shim، این اسکریپت را دوباره اجرا کنید.
- **لوکال روی ویندوز:** avr-gcc را (مثلاً از `ZakKemble/avr-gcc-build`) در PATH سرور dev بگذارید و وارد حساب شوید. بدون avr-gcc فقط فرم‌ویر آماده‌ی Blink اجرا می‌شود.

## همگام‌سازی Adafruit (قدیمی)

`npm run lab:sync` → `/opt/pushrsp/lab-assets` + `public/lab/catalog-index.json`. فایل‌های STEP خام داخل باندل JS کلاینت نمی‌روند. برای پیش‌نمایش سه‌بعدی جایگزینش شده با `lab:models` زیر.

## مدل‌های سه‌بعدی واقعی (`npm run lab:models`)

- منبع‌ها در `scripts/lab-models/sources.mjs` (هر قطعه: URL فایل STEP/FCStd، لایسنس، انتساب). ساخت با `scripts/lab-models/build.mjs`:
  دانلود (کش در `.cache/`، gitignore شده) → تبدیل با `occt-import-js` (OpenCascade/WASM) → رنگ‌آمیزی بر اساس رنگ واقعی هر وجه → ساده‌سازی و فشرده‌سازی با `@gltf-transform/*` و meshopt → خروجی در `public/lab/models/<id>.glb`.
- ۱۱ از ۱۶ قطعه مدل CAD واقعی دارند (Arduino Uno/Nano، LED، LED RGB، دکمه، پتانسیومتر، بازر، سروو، HC-SR04، LCD 1602، OLED). بقیه (بردبورد، دو مقاومت، DHT22، PIR) عمداً مدل درون‌کد دارند: منبع باز مناسب پیدا نشد یا مدل درون‌کد آموزنده‌تر است (رنگ‌بندی مقاومت واقعی، برخلاف مدل‌های بی‌رنگ CAD).
- `ModelViewer` اول `def.modelUrl` را با GLTFLoader بارگذاری می‌کند؛ در صورت خطا (شبکه یا تغییر منبع) به مدل درون‌کد برمی‌گردد — هرگز کرش نمی‌کند.
- برای چشمک زدن LED روی مدل واقعی، اسکریپت ساخت رنگین‌ترین متریال قطعه را `lab-glow` نام‌گذاری می‌کند؛ `ModelViewer` همان متریال را پیدا و emissive آن را روشن/خاموش می‌کند.
- لایسنس‌ها متفاوتند (MIT، CC-BY-3.0، CC-BY-SA-4.0) — انتساب per-part در `public/lab/models/CREDITS.md` (خودکار)، متن کامل در `src/lab/licenses/`، خلاصه در `/lab`.
- نیاز به اینترنت دارد؛ اگر GitLab با ۴۰۳ رد کرد، به‌خاطر fingerprint شبکه‌ی Node است — اسکریپت با `curl` دانلود می‌کند، نه `fetch`.

## محدودیت‌ها (صادقانه)

- SPICE کامل، اسیلوسکوپ واقعی، Logic Analyzer عمیق: خارج از محدوده MVP.
- Servo/HC-SR04: قالب و سیم‌کشی هست؛ رفتار آنالوگ کامل یا pulseIn واقعی محدود است.
- مدل ۳D: ۱۱ قطعه مدل CAD واقعی (ساده‌سازی‌شده) دارند؛ ۵ قطعه مدل ساده‌ی درون‌کد. جزئیات بالا.
- لینک اشتراک فقط در همان مرورگر باز می‌شود (localStorage)؛ اشتراک واقعی نیاز به ذخیره‌ی سمت سرور دارد.
- شبیه‌ساز فقط D13 (PORTB5) را گزارش می‌کند؛ LEDهای روی پایه‌های دیگر روشن نمی‌شوند.
